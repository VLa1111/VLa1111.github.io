THE SHIFT

从一个不可中断的 loop，变成可调度的步骤。

此前 H3 把整个 denoise loop 放在一次 forward() 内，一条请求会独占引擎。工作将其拆为 prepare_encode、denoise_step、step_scheduler 与 post_decode，让 runtime 能在 step 粒度做排布。

THE CONTRACT

共享的准备路径，避免两种执行模式悄悄分叉。

01

统一输入构建

request mode 与 step mode 共享准备与解包路径，使改变可被同一组正确性检查覆盖。

02

保持请求边界

将 co-batched 请求拼为一个 sequence，但 attention document 仍按请求隔离，避免跨请求 attention。

03

显式写出约束

不支持的 request-only 特性被明确拒绝，而非静默产生不一致结果。

THE RESULT

一个诚实的负结果，仍然是工程进展。

连续批处理实现了 scheduler-level control，却没有提升 H3 的端到端吞吐。PR 将测量和原因一并记录，而不是把“batching”包装为性能承诺。

为什么
